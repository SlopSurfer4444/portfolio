# Эксплуатация и проверка результата

## Как принимается изменение

1. Определяется точное устройство или сервис и его текущее состояние.
2. Сохраняются необходимые настройки и способ отката.
3. Изменение выполняется в ограниченном объёме.
4. Проверяется не только запуск службы, но и пользовательский результат или доступность с нужных источников.
5. Рабочая процедура сохраняется в runbook, чтобы решение не зависело от истории переписки.

Для сетевых ограничений используются положительные и отрицательные проверки. Для веб-продукта — тесты, сверка установленной версии, состояние БД и вход через браузер. Для обновления VPS — проверка после перезагрузки, включая VPN и внешний вход.

## Работа с неопределённым исходом

Timeout не означает, что команда не выполнена. Сначала читается сохранённое состояние и проверяется устройство. Повторный запрос не должен создавать вторую операцию с тем же назначением. Это особенно существенно при управлении питанием и данными.

При обновлении приложения откат касается версии приложения. История операций в БД не заменяется старой копией только ради возврата интерфейса.

## Что проверялось

| Проверка | Что она подтверждает |
|---|---|
| 18 реальных операций с девятью камерами | Работу цепочки пользователь → сервис → питание → проверка состояния |
| Повторная MFA и отмена через браузер | Прохождение нового входа и отсутствие запуска при отмене |
| Тесты брокера с имитацией устройств | Отказы при неверных разрешениях, привязках и повторениях без риска для рабочих данных |
| Разрешённые и запрещённые сетевые источники | Действие конкретных ограничений доступа |
| Reconnect агентов и удалённый терминал | Работоспособность обслуживания после обновления runtime |
| Проверки после перезагрузки VPS | Возврат внешнего контура в работу |

## Файлы и резервные копии

Четыре папки NAS зашифрованы с ручной разблокировкой администратором после перезапуска. При переходе проверялись сохранность файлов и права доступа. Ключи восстановления сохранены на двух независимых защищённых носителях.

Для Hyper Backup создан зашифрованный архив на внешнем диске. После первого копирования проверены пароль архива и чтение четырёх образцов с совпадением SHA-256. Для трёх архивов виртуальных машин выполнена нативная проверка VMA.

## Документация

Для обслуживания подготовлены реестр оборудования, runbook и подтверждения проверок. В реестре расходов сохраняются фактические покупки, отдельно от плановых оценок. Исторические материалы не считаются текущей инструкцией для повторного запуска.

Для сотрудников, руководителя и нового администратора подготовлены 13 документов Word на NAS. Они описывают работу с файлами и сканированием, оборудование, ВМ, DNS, внешний VPS, сервисы и оплаты, доступы и восстановление. Общая памятка и технические разделы имеют разные права доступа.

Публичный кейс содержит общую архитектуру и описание результатов. Реальные конфигурации, резервные копии, ключи восстановления и записи доступа хранятся отдельно.

## Работа с ИИ

ИИ использовался для разбора симптомов, подготовки кода, тестов и документации. Контроль оставался у исполнителя проекта: определить цель, проверить предложенное действие, сравнить фактический результат и принять пользовательский сценарий. Проверка включает тесты программной логики и отдельные сценарии на оборудовании.
